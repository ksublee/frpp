# Validation workflow

Use a short regression suite during development. Keep expensive fitting,
platform and statistical validation as separate checks.

## Daily regression suite

Install the current emhawkes and frpp source trees into your development R
library, then run from the frpp repository:

```sh
Rscript tools/validate-fast.R results/fast
# If emhawkes is not the sibling source directory:
Rscript tools/validate-fast.R results/fast /path/to/emhawkes
# Include the separate simulate/nobs work when installed from a matching tree:
Rscript tools/validate-fast.R results/extended /path/to/emhawkes --extended
```

The runner tests **installed implementations**, using tests from the source
checkout. Reinstall after changing package code. A version number alone does
not establish source identity. The report records library paths, source and
installed-code MD5 hashes, session information, per-file logs, elapsed times
and failures. It does not install packages or alter the source trees.

The shared-kernel development API is required; the runner fails before testing
if it is absent. It discovers every ordinary FRPP test and adds emhawkes's
public shared-kernel test. `--extended` additionally requires the separate
simulate/observation-count development tests and their matching implementation.
Missing selected files fail validation; they are not silently skipped. Each
file runs sequentially in a fresh R process.
Missing optional maxLik coverage is explicitly reported. Install maxLik to
exercise both optimizer providers.

| Area | Checks |
|---|---|
| Simulation | 36 legacy/new combinations; all common output fields and final RNG exactly equal; initial-only paths, seed restoration, callbacks, marks and counts |
| State recursion | 72 exact R/C++ comparisons, including multiple kernels, reordered/overlapping mapping, signed components and simultaneous events |
| Independent arithmetic | All-past-event intensity reconstruction and numerical integration, FRPP density/survival terms, exponential-law reduction to Hawkes, global refresh semantics |
| Estimation | Analytic small MLEs; two optimizers; fixed/shared/residual parameters; boundary and unidentified-curvature guards |
| New paired fit | Fixed 65-row observations; estimate baseline and excitation with beta and residual parameters fixed; old/new coefficients, likelihood, Hessian, covariance and initial state exactly equal; RNG unchanged |
| Saved objects and dispatch | New minimal R sessions, conversions, standard methods, nobs/AIC/BIC, fitted-model reconstruction |

The fixed observations were generated once by release source emhawkes 1.0.1
(0926075), not regenerated by the simulator being tested. The new paired test
uses exact comparisons within each optimizer. Different optimizers need not
return identical estimates. Independent replay retains the existing 1e-10
comparison tolerance; independent kernel integrals retain 1e-12. No tolerance
was increased to shorten validation.

## Saved large-fit replay

To re-evaluate the earlier 10,000-row fits with current code without rerunning
optimization, retain their original inputs and saved fits:

```sh
Rscript tools/replay-fit-validation.R /path/to/legacy-fit-results
```

This checks restored likelihoods, state histories, RNG preservation and the
known likelihood summation-order difference. It does not test whether a
changed optimizer still follows the same search or converges to the same fit.
Do not regenerate or overwrite the reference results during routine checks.

## Full validation

Before release, run full R CMD check, vignette rebuilding and platform CI.
Rerun the large paired fit when changing parameter mapping, optimization,
constraints, fitting reconstruction or likelihood behavior:

```sh
Rscript tools/validate-legacy-fit.R results/legacy-fit-new 3
```

Use a new output directory to preserve previous reference results. Keep
performance benchmarks separate, with warm-up, alternating execution order,
at least three repetitions and no concurrent heavy jobs. The daily suite is
not a performance benchmark or evidence of confidence-interval coverage.

## Local measurements, 2026-10-18

Windows, R 4.5.1, maxLik 1.5-2.1, emhawkes 1.0.1 development installation,
frpp 0.0.0.9000; both source trees already installed:

- Existing six FRPP files: 5.42 seconds including their R startups.
- New complete suite: 10/10 files passed; test loop 14.41 seconds;
  full command 15.65 seconds including parent R startup/report preparation.
- New paired fitting file: 2.45 seconds, both providers included.
- Earlier six 10,000-row fitting calls alone: 2,017.61 seconds (33.63 minutes).

These are different workloads, not a claim that the optimizer became faster.
The new suite checks numerical contracts frequently; it does not replace the
large six-parameter joint fit or its statistical diagnostics. Simply reducing
that large example to 128 rows produced nonfinite Hessian entries in a trial.
The small paired fixture therefore fixes weakly identified coordinates rather
than treating a degenerate fit as acceptable.

In isolated R sessions, an intentional extra RNG draw and a 1e-5 kernel-integral
error each failed the expected assertion. Package files were not modified by
these fault checks. Full package and platform checks were not rerun for this
test/tool-only change. No package calculation code changed.

## S4 follow-up

After converting fspec to S4, the suite discovers eight FRPP files plus the
three emhawkes files. The new specification test checks typed slots, semantic
validity, accessors, legacy S3 conversion, callback preservation and dual
S3/S4 dispatch. The final 2026-10-18 run passed all 11 files in 15.58 seconds
including parent R startup/report preparation. Saved 10,000-row fits replayed
in 28.16 seconds without optimization. See [S4 results](fspec-s4-results.md).

## Public-kernel scope

The default suite now uses only the published common-kernel contract: eight
FRPP files and one emhawkes kernel file. The two tests for separately pending
simulate/nobs work require `--extended`. The earlier 11-file measurements above
refer to that broader development tree. This separation lets the default suite
run against the exact common-kernel-only emhawkes publication.
